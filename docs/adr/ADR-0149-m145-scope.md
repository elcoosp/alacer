# ADR-0149: M145 scope — the subscribe gate persists across reconnects

- **Status:** Accepted (2026-11-23)
- **Implements:** the kill-switch ADR-0146 pre-registered — a consumer needs the M142 subscribe gate to persist across reconnects, and today it dies with the session: every reconnect greets the whole stream and re-asks blind, the panel's own tier selection lost on every reload.
- **Companion:** ADR-0146 (the subscribe ask), ADR-0144 (the replay cursor — the greeting's `facts` precedent), ADR-0010 (the wire protocol's versioning rule); architecture §13.3, §17, §18 (the M145 row); `docs/inspector-protocol.md` (the normative wire document).

## Decision

M145 grows the greeting beside the cursor's `facts` precedent, exactly the shape ADR-0146's kill-switch pre-registered: "grow the greeting beside the cursor's `facts` precedent (the server remembering a panel is a second channel, priced first)." The server remembers one gate — the filter the last session's `subscribe` ask left behind, held on the [`InspectorServer`](../../crates/alacer-inspect/src/server.rs) as one shared cell across sessions — and every new session starts under it instead of the whole stream: a reconnecting panel reads its own ask back from the greeting's new `gate` field ([`Hello::gate`](../../crates/alacer-inspect/src/wire.rs), `Option<Vec<Tier>>` — `null` the whole stream, a list the named tiers in the event vocabulary's order, the empty list the mute; the vocabulary and order are `TierFilter::ask`'s, the inverse of the M142 `from_ask`, one vocabulary two doors) instead of re-asking blind. Re-asking stays welcome, and the ask's shape is what the next session greets with — the three shapes persist exactly as the asks named them. The memory is the server instance's, one panel's worth: a fresh server greets the whole stream (the shape every pre-M142 session rode), and a consumer that rebinds a new server gets a fresh memory with it. The gate stays the *session's* fan-out and never the recorder's capture — the rings keep recording every tier, the replay and stats asks answer whole, the mute honest silence (ADR-0146's rule, unchanged). The memory's price is named first, per the kill-switch's own words: the connect-time cost rides the reconnect gate bench (`gate/greeting_ask_3`, `gate/reapply_512x3_filtered` — the greeting's field build beside the reconnecting session's first filtered drain, on the replay bench's steady-state batch), *outside* the published corpus (the coordinated rule grows the baseline at the next published cut, never at a bench file's). Not in this milestone: throttling the muted tiers into a queued delivery — ADR-0146's second kill arm refuses it as a second queue; the rings are the durable history, the gate a live-stream shape.

## Consequences

- **A panel's tier selection survives its own reload.** The frame-ledger panel that gated to `["frames"]` reconnects into its gate — the greeting names it before the panel can ask — and the input storm's fan-out stays silent across the reload; the mute-while-reading panel's quiet survives the digest pause. The panel's own silence, never a loss: the rings held every tier through every reconnect (ADR-0146's rule), and now the fan-out agrees with what the panel last asked.
- **The greeting is the memory's only wire surface.** No new control, no version bump: the `gate` field rides `version: 1` additively (the `facts` field's rule — clients that ignore unknown fields are unaffected), and a panel that never subscribed greets `"gate":null` byte-for-byte the pre-M145 shape beside the new field's absence-era pins re-agreed in the same cut.
- **The kill arms stay pre-registered.** A consumer needing the gate to *throttle* instead of dropping gets the refusal ADR-0146 wrote (a second queue); a consumer needing per-panel memories (many simultaneous panels, each its own gate) grows the greeting beside a session identity — a second channel priced first, never smuggled into the filter's vocabulary.
